# Lucky Streak — Release HQ

Use this repository as the band's shared workspace for planning and tracking each song release. Keep work visible, assign one clear owner to every task, and use issues for anything that needs action.

## Start here

1. Create a GitHub **Project** for the release (for example, `Next single — [song title]`) and add a board view with these status columns: **Backlog**, **Ready**, **In progress**, **Blocked**, and **Done**.
2. Add the band members as collaborators and make sure each person can access the repository and Project.
3. Create one issue per task from the **Band task** template. Assign one accountable person, set a due date, and add labels such as `writing`, `recording`, `artwork`, `promo`, or `release` as useful.
4. Add those issues to the Project. Keep the Project status current and link dependent tasks in the issue descriptions or comments.
5. Copy `RELEASE_PLAN.md` for each new song, fill in the details, and commit it under `releases/<song-title>/RELEASE_PLAN.md`.

## Suggested release stages

- **Plan:** confirm song version, release date, platform/distribution plan, budget, and owners.
- **Prepare:** finish recording, editing, mixing, mastering, artwork, credits, and metadata.
- **Promote:** prepare announcement, social assets, press outreach, and any video or live content.
- **Release:** verify distribution and links, publish scheduled posts, and coordinate launch-day activity.
- **Follow up:** share results, archive assets/links, and capture lessons for the next release.

## Team habits

- Every task has one directly responsible owner, a due date, and a clear definition of done.
- Break broad work into small issues; avoid assigning an issue to the whole band.
- Use **Blocked** when someone cannot proceed, and comment with what is needed and from whom.
- Review the board together regularly (weekly is a good starting point) and adjust priorities or dates.
- Keep sensitive information (passwords, private keys, payment details) out of issues and this repository.

## Release files

Keep shared plans and non-sensitive release materials in `releases/<song-title>/`. Store large audio/video files using a suitable shared drive or media service and link them here rather than committing them to Git.
